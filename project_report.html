2. Introduction

A Complete Blood Count (CBC) is one of the most critical diagnostic evaluations performed in healthcare. It assesses the cellular components of circulating blood, focusing principally on:

  • Red Blood Cells (RBC): Erythrocytes that transport oxygen from the lungs to bodily tissues and return carbon dioxide.
  • White Blood Cells (WBC): Leukocytes that drive immunological defense against infections and inflammation.
  • Platelets (Thrombocytes): Cellular fragments crucial for hemostasis, vascular repair, and blood clotting.

In Health Informatics, computational systems such as Laboratory Information Systems (LIS) and Clinical Decision Support Systems (CDSS) structure, validate, and compare physiological observations against standardized demographic reference intervals. The Blood Cell Count Analyzer provides an educational, console-based simulation of this workflow, built explicitly with foundational Python constructs: conditional branches, loops, functions, lists, and dictionaries.

3. Problem Statement

Manual inspection of laboratory hematology reports by non-clinical learners is prone to comparison mistakes, misinterpretation of gender-differentiated normal intervals, and unnecessary anxiety due to premature self-diagnosis.

Technical Challenge: To design and implement a beginner-friendly, modular Python software application using core concepts from CSE1021 that automates laboratory data input, validates input formats, evaluates values against gender-aware reference intervals, aggregates statistical counts, and generates an aligned report accompanied by strict non-diagnostic educational disclaimers.

4. Functional Requirements

Module Key Features & Functional Deliverables
Module 1: Patient Information Captures and validates Patient Name (non-empty), Age (positive integer 1–125), Gender (Male/Female/Other), and assigns unique Sample ID.
Module 2: Blood Data Entry Prompts for RBC, WBC, and Platelet counts with specified medical units. Robustly catches and reprompts on non-numeric, negative, or zero inputs.
Module 3: Blood Analysis Matches gender-specific ranges for RBC and adult baselines for WBC/Platelets. Categorizes values as LOW, WITHIN RANGE, or HIGH. Calculates summary counts.
Module 4: Report Generation Builds an aligned tabular report showing parameters, observed values, reference intervals, status, summary statistics, and disclaimers.
Module 5: Session Storage & Search Stores records in an in-memory list of dictionaries. Provides summary listing and linear search by patient name or sample ID.

5. Non-Functional Requirements

  • Usability: Intuitive terminal menu with explicit unit hints (e.g., million cells/mcL, e.g., 4.8) and continuous loop navigation.
  • Reliability & Crash Resilience: Uncaught runtime exceptions are prevented using try-except ValueError blocks embedded in while True validation loops.
  • Maintainability: Clean separation of concerns across 6 Python files. Reference ranges are isolated within a single dictionary (reference_ranges.py).
  • Performance: Instantaneous computation and linear search execution (< 10 ms).
  • Resource Efficiency: Uses standard library only (zero external pip packages); RAM usage is under 25 MB.
  • Ethical Transparency: Prominent educational disclaimers prevent medical misinterpretation.

8. Design Decisions & Rationale

  • Modular Architecture: Decoupling validation, analysis, reference data, storage, and reporting allows each file to adhere to the Single Responsibility Principle and simplifies unit testing.
  • Standard Library Exclusivity: Eliminates pip version mismatches across student environments, ensuring the project runs seamlessly on any standard Python 3.8+ interpreter.
  • In-Memory Python Lists and Dictionaries: Highlights core first-year syllabus concepts (dictionary lookups, list iteration, linear search) without the overhead of external SQL engines.
  • Deterministic Rules vs. ML: Clinical reference ranges are legally regulated physiological thresholds, making rule-based conditional branches (if-elif-else) transparent and accurate.
  • Strict Non-Diagnostic Educational Stance: Abnormal parameters are reported as mathematical deviations, reinforcing safe clinical informatics ethics.

12. Challenges Faced

  • Clinical Unit Discrepancies: RBC is measured in million cells/mcL, whereas WBC and platelets are in whole counts/mcL. Solved by embedding explicit format hints in the CLI prompts.
  • Crash Prevention: Non-numeric user inputs were handled using try-except ValueError inside while True loops.
  • Gender Sensitivity: Solved by using gender-keyed nested dictionaries for RBC thresholds.
  • Medical Ethics: Guarded against speculative diagnoses by framing findings as mathematical reference comparisons.
